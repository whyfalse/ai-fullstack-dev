# modules.json 规则说明

项目管理目录根下存在一个 `modules.json`，登记项目的全部代码模块，是全项目"有哪些端、谁依赖谁"的**唯一事实来源**，入库共享。

前端、后端只是代码模块的两个特例；多端项目（Web、小程序、App、管理后台、多个后端服务、共享组件库）均在此登记。经典双模块项目的 `modules.json` 默认登记 `frontend` / `backend` 两个模块。

## 字段说明

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| `id` | string | 是 | 模块 ID，全项目唯一，小写英文、不含空格。作为开发者 Agent 命名后缀（`<id>-developer`）、看板文件名（`dev-tasks/<id>.md`）、设计文档文件名（`architecture/module/<架构模块>/<id>.md`）、任务编号后缀（`-<id>`）以及 `setting.local.json` 的 `modules.<id>` 键 |
| `name` | string | 是 | 模块的人类可读名称（可用中文） |
| `type` | string | 是 | 模块类型，暂定 `frontend` / `backend` 两值（`library` 延后到共享库治理时评估）。决定开发者读取 dev-thinking 技能的哪个端文件（`frontend`→`dev-thinking/frontend.md`，`backend`→`dev-thinking/backend.md`；通用原则 `dev-thinking/SKILL.md` 按需查阅） |
| `owner` | string\|null | 否 | 数据库表归属：本模块名下数据库表的归属模块 ID，写入各表的 `owner` 字段（见数据库契约模板）。后端服务通常自属（`owner` = 自身 `id`）；前端/消费端模块不拥有表，填 `null`。多后端服务时，某服务使用的表若由另一服务拥有，`owner` 指向实际拥有者 |
| `dependsOn` | string[] | 否 | 依赖的模块 ID 列表。**仅作信息标注**（供架构师评估破坏性变更影响面、契约目录的提供方/消费方标注），**不参与任务排序**——契约先行保证各端并行开发，提供方是否完成不阻塞消费方。无依赖时为空数组 |

## 结构示例（经典双模块）

```json
{
    "modules": [
        {
            "id": "frontend",
            "name": "前端",
            "type": "frontend",
            "owner": null,
            "dependsOn": []
        },
        {
            "id": "backend",
            "name": "后端",
            "type": "backend",
            "owner": null,
            "dependsOn": []
        }
    ]
}
```

```json
{

        {
            "id": "api",

            "type": "backend",
            "owner": "api",
            "dependsOn": []

        {

        }

```

## 校验规则（初始化/升级时执行）

- **ID 唯一**：所有模块的 `id` 不得重复。
- **路径存在**：每个模块在 `setting.local.json` 的 `modules.<id>.projectPath` 中登记的路径必须存在（路径是个人配置，不入库，见 `开发管理设置模板.md`）。
- **依赖不成环**：`dependsOn` 声明的依赖关系不得构成环（如 A 依赖 B、B 依赖 A）。依赖仅作信息标注，不影响任务排序。

## 维护说明

- 该文件由初始化流程写入，登记初始化时确认的全部代码模块。
- **中途新增/移除一个端**：走升级流程的升级分支（用户触发收集新模块的 ID/名称/类型/路径），补 `modules.json` + 生成对应开发者 Agent + 登记目录授权 + 建看板；架构师不负责结构注册。
- `modules.json` 记录的是**结构事实**（有哪些模块、类型、归属、依赖），不含个人路径——路径统一放 `setting.local.json`（个人配置、不入库）。
- 谁需要知道"有哪些端、谁依赖谁"，就读本文件，不靠记忆和硬编码。
