# AI 全栈开发工作流

`ai-fullstack-dev` 是一个用于创建 AI 全栈开发项目的技能。它通过定义需求分析师、架构师、开发者、测试者、项目经理等 Agent 角色，结合标准化的 Rules、Skills 和模板，形成一套从需求到交付的结构化开发方法。

工作流：需求分析 → 架构设计（契约优先）→ 任务分配 → 各模块并行开发 → 测试。

所有框架产物（Agent、Rules、Skills、看板、配置）统一安装在项目管理目录；代码仓只被读写、不写入任何框架文件。项目中的全部代码模块登记在 `modules.json`，各模块的代码仓路径记录在 `setting.local.json`。

## AI Agent 角色

| Agent | 职责 |
| ----- | ---- |
| 需求分析师 | 需求分析与模块拆分，将产品需求细化为结构化模块需求文档 |
| 架构师 | 架构设计与契约定义，产出程序功能设计、API 契约、数据库建模与任务分配 |
| 开发者 | 按模块生成（`<moduleId>-developer`），直接操作对应代码仓，严格遵循契约 |
| 测试者 | 依据 `test.md` 功能用例验证实现，读取测试配置生成测试报告 |
| 项目经理 | 以子代理方式派发各阶段角色，门禁转达用户批复与断点续跑（需 AI 工具支持子代理派发） |

## 项目目录结构

```text
/
├── README.md                    # 项目简介
├── modules.json                 # 代码模块注册表（ID/名称/类型/归属/依赖），入库共享
├── setting.local.json           # 个人设置（模块路径映射），不入库
├── framework.json               # 框架元信息（名称/版本/初始化日期）
├── requirements/                # 需求管理目录
│   ├── docs/                    # 通用需求文档目录
│   └── module/                  # 模块级需求目录
│       ├── catalog.md           # 需求模块目录
│       └── <模块名称>/          # 单个模块需求文件夹
│           ├── README.md        # 需求模块文档
│           └── change-log/      # 变更日志
├── architecture/                # 架构设计目录
│   ├── README.md                # 架构设计说明（含各模块技术选型）
│   ├── module/                  # 程序功能模块
│   │   ├── catalog.md           # 程序功能模块目录
│   │   └── <模块名称>/          # 单个程序模块
│   │       ├── <moduleId>.md    # 代码模块功能文档（按模块 ID 命名，仅涉及模块出文件）
│   │       ├── test.md          # 功能测试用例
│   │       └── change-log/      # 变更日志
│   └── contracts/               # 架构契约
│       ├── apis/                # API 接口契约
│       │   ├── catalog.md
│       │   ├── interfaces/      # 接口定义
│       │   └── params/          # 出入参定义
│       └── database/            # 数据库契约
│           ├── catalog.md
│           ├── <表名>.json      # 表/集合 schema 中立描述
│           └── change-log/      # 数据库变更日志（按表名分文件）
├── dev-tasks/                   # 开发任务拆分目录
│   ├── <moduleId>.md            # 各代码模块的任务看板
│   └── pipeline-log.md          # 流水线运行日志（项目经理追加式写入）
├── tester/                      # 测试者工作目录
│   ├── config.md                # 全局测试配置
│   ├── config.local.md          # 私人测试配置
│   └── reports/                 # 测试报告
└── templates/                   # 模板目录
```

## 开发工作流

```text
用户需求
  │
  ▼
需求分析师 ──► 需求分析、模块拆分，输出结构化需求文档
  │
  ▼
架构师 ──────► 程序功能设计、API 契约、数据库建模、功能测试用例、任务分配
  │
  ▼
各模块开发者 ──► 基于契约并行开发
  │
  ▼
测试者 ──────► 依据 test.md 验证实现，生成测试报告
```

需求模块与架构模块不要求同名或一一对应；一次需求变更可落到多个架构模块，契约统一设计，变更日志、变更ID 与任务按模块独立产出。

各阶段也可由项目经理统一编排：项目经理依次派发各角色子代理自动推进，所有契约门经项目经理转达用户批复。

## 快速开始

### 前置条件

- 已安装支持自定义 Agent / Skill（或等价机制）的 AI 编码助手
- 已将本仓库作为可用技能接入助手
- 已准备一个空目录作为项目管理目录（dev-manager 空间）
- 各代码模块的代码目录已就绪（路径确定）

### 初始化项目

1. 在项目管理目录下调用 `ai-fullstack-dev` 技能启动初始化
2. 按提示确认当前目录作为项目根目录，输入各代码模块的信息（模块 ID / 名称 / 类型 / 代码仓路径 / 依赖），并选择新项目使用的 AI 工具
3. 系统按所选 AI 工具的约定生成 Agent 配置、Rules 与 Skills，全部落于项目管理目录；代码仓不安装任何框架文件
4. 检查生成的 `modules.json`（模块注册表）与 `setting.local.json`（模块路径映射）是否正确

### 升级已有项目

框架模板源更新后，已初始化的项目通过升级流程同步：

1. 在项目管理目录下再次调用 `ai-fullstack-dev` 技能，表达升级意图
2. 技能比对项目内已安装产物与模板源的差异，生成变更清单（新增 / 冲突）供确认
3. 确认后执行同步并更新 `framework.json` 的版本号；项目业务数据不比对、不覆盖、不删除

### 开始开发

1. 调用需求分析师 Agent，输入产品需求，生成结构化需求文档
2. 调用架构师 Agent，基于需求进行架构设计和任务分配
3. 调用开发者 Agent（`<moduleId>-developer`），按任务清单开发
4. 通过各模块任务看板 `dev-tasks/<moduleId>.md` 追踪进度（`todo` → `in-progress` → `done`）

## 注意事项

- 契约门（模块拆分、设计、编码清单、契约违反等）需人工批复，各阶段也支持用户手动调用
- 有副作用或不可逆的操作（DDL 执行、数据库迁移、路径配置）由开发者自行处理，Agent 不代替执行
- 代码仓与项目管理目录之间的路径互引仅靠 `setting.local.json`，配置错误会导致 Agent 找不到契约或任务
