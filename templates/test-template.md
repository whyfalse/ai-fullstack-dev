# 功能测试用例模板（test.md）

> 本模板定义 `architecture/module/<模块>/test.md` 的结构。架构师生成 test.md 时按此结构编写，测试者按此结构解析与校验。

## 结构

- 按功能点分节：`## 功能点：<名称>`
- 每条用例强制稳定编号：`TC-<功能点缩写>-<序号>`
  - 功能点缩写为大写字母缩写（如 `LOGIN`、`REG`），不含连字符
  - 序号从 0 起，在同一功能点内递增
- 每条用例四要素：描述 / 输入数据 / 预期结果 / 类型
  - 类型取值：`正常` / `边界` / `异常`

## 示例

```markdown
# 功能测试用例: <模块名称>

## 功能点：用户登录

### TC-LOGIN-0 正常登录
- 描述：已注册用户用正确账号密码登录
- 输入数据：账号 user1 / 密码 Pass123
- 预期结果：返回 token，状态 200
- 类型：正常

### TC-LOGIN-1 密码错误
- 描述：已注册用户密码错误
- 输入数据：账号 user1 / 密码 wrong
- 预期结果：返回错误码 401，提示"账号或密码错误"
- 类型：异常

### TC-LOGIN-2 密码边界长度
- 描述：密码长度恰好为下限（8 位）
- 输入数据：账号 user1 / 密码 12345678
- 预期结果：通过校验进入登录流程
- 类型：边界

## 功能点：用户注册

### TC-REG-0 正常注册
- 描述：新用户提交合法注册信息
- 输入数据：账号 user2 / 密码 Pass123 / 邮箱 user2@example.com
- 预期结果：创建成功，返回用户ID，状态 201
- 类型：正常
```

## 约定

- 功能点名称须与 `frontend.md` / `backend.md` 中的功能点对应，便于模块 change-log 的"受影响功能点"小节定位 test.md 用例。
- 用例编号一经分配保持稳定，不得重排或复用。
- 类型仅限：正常 / 边界 / 异常 三类。
