---

## 流程
1. 确定项目管理根目录 `devManagerPath`：开发者 Agent 统一运行于项目管理目录，`devManagerPath` 即当前工作目录。

2.  读取 `<devManagerPath>/dev-tasks/<你的模块ID>.md`（模块 ID 见你的 Agent 定义，如 `frontend` / `backend`），按以下顺序确定本次要开发的任务：
    - **用户已指定任务**（提示词中给出了任务编号或关联的变更；派遣模式下任务由项目经理的派发提示指定，同样命中本分支）：在看板中定位对应任务行。该行状态为 `todo` 则以其为本次任务；为 `in-progress` 说明上次开发中断，先读该行**备注**中的断点标记（如"等待编码清单确认"），结合派发提示中的门禁批复记录与已完成步骤摘要，从断点继续、不重做已完成步骤；为 `blocked` 则停止并说明阻塞原因（由用户——手动模式——或项目经理——派遣模式——解除阻塞后改为 `todo`）；为 `done` 则提示任务已完成并结束。
    - **用户未指定任务**：列出看板中所有状态为 `todo` 的任务（含任务编号、关联的变更、描述），让用户选择其一后再继续；若无 `todo` 任务，输出"无待开发任务"并结束。
    - **不主动挑选 `blocked` 任务**（由用户——手动模式——或项目经理——派遣模式——解除阻塞后改为 `todo`）。

3. **读取本次变更对应的变更日志**，获取本次任务的真正需求来源：
   - 从任务行中取出**所属模块**列与**关联的变更**列。所属模块为**架构模块**（与 `architecture/module/` 下文件夹名一致）；需求模块与架构模块不要求同名，需求背景通过模块 change-log 的"关联需求变更"小节回溯定位。
   - 关联的变更为变更ID，形如 `<任务简介>-<YYYYMMDD>-<seq>`，截取其中的 `<YYYYMMDD>-<seq>` 段。
   - 读取 `<devManagerPath>/architecture/module/<所属模块>/change-log/<YYYYMMDD>-<seq>.md`，理解本次变更具体新增/修改了哪些 API、表、交互或逻辑。
   - 变更日志是 task 级的需求来源；模块全量设计文档（`<moduleId>.md`）作为背景按需查阅，不作为本次任务范围的权威依据。
   - 若关联的变更为空或变更日志文件不存在，停止开发并报告"任务 `<编号>` 缺少关联的变更或对应的变更日志 `<YYYYMMDD>-<seq>.md` 未找到，请确认架构师是否已分配变更并生成变更日志"。

4. 更新 `<devManagerPath>/dev-tasks/<你的模块ID>.md` 中对应任务下的状态为开发中。

5. 开始开发。

6. 开发完成后，更新 `<devManagerPath>/dev-tasks/<你的模块ID>.md` 中对应任务下的状态为 `done`（派遣模式下由项目经理回读校验）。

## 派遣模式补充（由项目经理派发时）

- 任务由派发提示指定（含 任务编号 / 关联的变更 / 所属模块），不触发"让用户选择任务"分支。
- 输出 GATE 段落**前**，先在本任务行**备注**追加断点标记（如"等待编码清单确认"、"等待契约违反处理"）再结束；批复后（续接或重派兜底）从断点继续，并清除该标记。
- 状态流转（`todo` → `in-progress` → `done`）仍由本流程写入；项目经理只回读校验，不代写。
