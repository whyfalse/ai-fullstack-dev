> 本技能不替代通用编程知识，只补充本项目下 AI 开发者**容易遗漏或做错**的场景。
> 本文件为所有模块类型共用的**通用原则**；各模块类型特有的约束与自检项在同级端文件（`frontend.md` / `backend.md`）中，按开发者所属模块的 `type`（见项目管理空间 `modules.json`）读取对应文件。**本文件与端文件必须同时阅读、同时遵循。**

## 强制要求：注释规范

本项目的代码会被 AI 开发者反复读取与修改，注释是 AI 理解项目意图的主要线索，以下为**强制**要求：

- **文件头注释**：每个脚本文件顶部必须有一段文件头注释，说明文件职责、所属模块、对外暴露内容。
- **函数注释**：每个非私有函数必须有职责、参数、返回值、可能异常的说明。
- **关键行注释**：以下场景必须加行内注释——业务规则相关的魔法数字、绕过框架默认行为的 hack、与契约绑定的字段映射、临时方案/TODO。各模块类型特有的补充触发场景见端文件。
- **注释随代码演进**：修改代码必须同步修改注释，删除代码必须连同注释删除。过时注释会误导后续修改。
- **不写废话注释**：不重复代码已表达的内容，只解释"为什么"和"非显而易见的约束"。

## 通用易错场景约束

### 契约校验在边界
- **入口校验一次**：在外部数据进入的入口处（前端为 API 响应、props、URL 参数；后端为控制器请求参数）校验一次，内部代码信任已校验数据，不层层重复校验。

### 变更范围
- **最小化变更**：修改既有代码只改必须改的部分，不顺手重构。重构应有独立任务。
- **废弃不删除**：暂时不用的代码标记 `@deprecated` 并注明替代方案与计划下线时间，给调用方迁移窗口。
- **保留决策痕迹**：重要的设计决策、绕路方案、临时妥协在注释中记录原因，否则后续无法追溯。

## 通用自检清单

提交前对照检查（须与本模块类型端文件的自检清单一并逐项核对）：

- [ ] 文件头、函数、关键行注释齐全且与代码同步
- [ ] 边界校验在入口完成，内部不重复防御
- [ ] 既有代码只做必要变更，未顺手重构
- [ ] 废弃代码已标记 `@deprecated` 而非删除
